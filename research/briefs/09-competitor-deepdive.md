# 09 — Competitive Intelligence Deep-Dive: Aerospace AI Skills & Adjacent Winners

**Date:** 2026-08-30 · **Author:** AeroSkills research (subagent) · **Status:** Evidence-backed, all figures measured via live web extraction on 2026-08-30 unless noted

**Headline verdict:** The whitespace is real and larger than expected. Every aerospace-skills attempt is a single-author hobby project (max 105★ — LunCoSim/lunco-sim, and it's a simulation platform, not a skills library). Meanwhile, two adjacent winners — cybersecurity skills (~31.7k★) and scientific skills (39.5k★) — proved the exact playbook AeroSkills needs, and the distribution standard (agentskills.io + SEP-2640 skills-over-MCP) is being standardized *right now*. Nobody has executed the cybersecurity-skills playbook in aerospace. The window is open.

### 1.1 devideamax/aerospace-team — 13★ measured 2026-08-30 (live 2026-08-31: 21★; task brief said 16; 0 watchers, 0 forks)

- **Attribution-encumbered license** ("MIT + Attribution", must keep attribution in frontmatter) — fine for personal use, poison for enterprise adoption.
- **No community (devideamax/aerospace-team):** 0 forks, 0 issues, 0 PRs, 10 commits, single author + factory-generated.

## Part 2 — The winners: exact templates to copy

### 2.1 Anthropic Cybersecurity Skills (mukul975/Anthropic-Cybersecurity-Skills) — ~31.1–31.2k★ (skillsllm.com measured 31,136; brief says 31,246)

*Note: despite the name, this is a community repo (mukul975), not Anthropic-owned — the name rides the Claude ecosystem. That branding choice itself is a lesson.*

**Numbers:** 817 structured skills (grew from 734 at v1.0.0), 29–34 security domains, mapped to **6 industry frameworks** — MITRE ATT&CK (all tactics, 200+ techniques), NIST CSF 2.0 (all 5 functions), MITRE ATLAS, MITRE D3FEND, NIST AI RMF, MITRE Fight Fraud (F3). Apache-2.0. Claims 20+ agent platforms. 3.2k+ forks-scale community.

**Exact structure (copy this):**
```
skills/<skill-name>/
├── SKILL.md              # YAML frontmatter + Markdown body
│   ├── Frontmatter:  name, description (keyword-rich), domain, subdomain, tags,
│   │                  atlas_techniques, d3fend_techniques, nist_ai_rmf, nist_csf
│   ├── When to Use     # trigger conditions for agent activation
│   ├── Prerequisites   # tools, access, environment
│   ├── Workflow        # step-by-step execution with commands + decision points
│   └── Verification    # how to confirm success
├── references/
│   ├── standards.md    # framework mappings (ATT&CK/CSF/ATLAS/D3FEND/AI RMF)
│   └── workflows.md    # deep technical procedure reference
├── scripts/            # working helper scripts (functional, not placeholders)
└── assets/             # templates, checklists
```

**What made it the winner (deconstruct):**
1. **Framework mapping is the moat, not the skills.** "Mapped to six frameworks" is the entire marketing thesis; ATT&CK coverage tables + **ATT&CK Navigator layers shipped per release** give visual, auditable coverage. It's a *standards-alignment product* wearing a skills library.
2. **Standard compliance:** agentskills.io format, "write once, use everywhere."
3. **Distribution:** `npx skills add mukul975/Anthropic-Cybersecurity-Skills` one-liner; releases with changelogs; issue templates (new skill / bug / feature request).
4. **Quality signals:** consistent frontmatter schema, validation steps in every skill, functional scripts.
5. **Domain breadth as PR:** 26→34 domains across releases shows momentum; "largest open-source cybersecurity skills library" is a self-fulfilling claim.
6. **Apache-2.0** (enterprise-safe) vs competitors' restrictive or absent licenses.

### 2.3 anthropics/skills + agentskills.io — the format itself

- **anthropics/skills:** ~172k★ (one of the most-starred repos in GitHub history), 20.5k forks, created 2025-09-22. Layout: `skills/` (creative/design, dev/technical, enterprise/comms, document skills incl. source-available docx/pdf/pptx/xlsx), `spec/` (the Agent Skills spec), `template/` (starter). `skills.sh` badge. Apache-2.0 + source-available split.
- **agentskills.io spec (the standard):** skill = directory with required `SKILL.md` (YAML frontmatter + Markdown). Frontmatter: `name` (required, 1–64 chars, lowercase-kebab, must match directory), `description` (required, ≤1024 chars, "what + when", keyword-rich for agent retrieval), `license`, `compatibility`, `metadata` (arbitrary KV), `allowed-tools` (experimental). Optional dirs: `scripts/`, `references/`, `assets/`. **Adopters include Gemini CLI, Junie, ZeroClaw, OpenCode, OpenHands, Autohand, and 20+ more** — cross-harness is now the baseline expectation, not a differentiator.

## Part 3 — The MCP ecosystem

### 3.1 Skills Over MCP Working Group & SEP-2640

- **Origin:** native skills support in hosts → SEP-2076 ("Agent Skills as a First-Class MCP Primitive") raised open questions → Interest Group (2026-02-01) → **Working Group (2026-04-16)**.
- **Leadership:** Ola Hungerford (Nordstrom / MCP maintainer) + Peter Alexander (**Anthropic**, core maintainer) — Anthropic is *in the room defining the standard*.
- **Current direction — SEP-2640 "Skills Extension"** (Extensions Track, extension ID `io.modelcontextprotocol/skills`, draft, v1 scope pinned 2026-07-16): skills are served **as Resources** (`skill://` URIs, `resources/read`, `resources/directory/read` behind a `directoryRead` capability). Rationale: "Skills are files; Resources exist to expose files" — no new primitive, inherits URI addressability/subscriptions/client tooling. **A server that doesn't implement it is unaffected; a client that doesn't see it sees ordinary resources.** Backward-compatible by construction.
- **Reference repo:** modelcontextprotocol/experimental-ext-skills — 196★, 29 forks, 83 commits, Apache-2.0; contains sep draft, use-cases, approaches, threat model, decision log, related-work survey.
- **Known divergence to migrate:** FastMCP's widely-used **SkillsProvider** (per-skill `_manifest` vs central index, different URI structure, different metadata mapping) — coordination is a near-term WG priority. **If AeroSkills ships a FastMCP-based skills server, design it SEP-2640-conformant, not FastMCP-conformant.**
- **Related workstreams:** Registry WG (skills.json proposal, champion JAORMX), Agents WG (skill activation), Primitive Grouping WG (progressive disclosure), coordination with agentskills.io (content format + well-known URI discovery).
- **Success criteria:** short-term = documented consensus; medium = convention-vs-extension recommendation (SEP-2640 is the direction); long = **interoperable skill distribution across MCP servers and clients**.
- **Why it matters to AeroSkills:** this is the future distribution channel for skills (serve your library over MCP, discoverable via registries). Being spec-conformant from day one + participating in the WG (comments on SEP-2640, skills.json proposal) = first-mover credibility at the protocol level.

## Part 5 — The first-mover question

### Why nobody has done this well (structural reasons, in order of weight)

1. **No ready-made machine-readable spine.** Cybersecurity won because MITRE ATT&CK + NIST CSF gave a free, universally-licensed, machine-readable taxonomy to map against. Aerospace standards are fragmented, partly paywalled (DO-178C, ASD-STE100 cost money; ECSS is free but sprawling), and **no organization publishes a machine-readable clause map**. Building the spine (DO/ARP/ECSS/FAR mapping) is hundreds of hours of expert work — the actual moat, which is why nobody has done it.
2. **Format is younger than the aerospace community's adoption curve.** Skills exploded only after Sept 2025 (anthropics/skills). Aerospace engineering is a conservative, enterprise, certification-obsessed field that trails tooling by 12–24 months. The 11 attempts are mostly hobbyists discovering skills in 2025–26.
3. **Liability fear.** Every aerospace MCP server carries an "educational only, not certified" disclaimer. Aerospace professionals default to "an AI agent must not design flight hardware" — nobody has framed skills as *knowledge/process augmentation inside certified workflows* (the framing Cybersecurity used: investigation support, not replacement).
4. **Small, fragmented community.** Aerospace on GitHub = simulation libs and OSINT tools, not knowledge assets. No equivalent of the security-researcher culture that poured 817 skills into the cybersecurity repo.
5. **The winners in adjacent domains had a wedge:** Cybersecurity had frameworks; Science had 100+ databases/APIs to skill-ify. Aerospace has neither an obvious spine nor a database goldmine — the wedge must be *built* (standards mapping + curriculum), which is expensive.
6. **All 11 attempts are single-author, zero-marketing, zero-distribution projects.** Max adoption (Soljourner's 60★) belongs to a 3-commit repo that died. There is no evidence of anyone trying the full playbook even once.

### What it takes to win (the AeroSkills playbook, synthesized from Parts 2–4)

1. **Build the spine first, publish it as the marketing artifact.** Aerospace standards map (DO-178C/DO-254/ARP4754B/ARP4761A/ECSS/AS9100D/14 CFR) rendered as a coverage dashboard — the aerospace equivalent of the ATT&CK Navigator. This is the 30k+★ moat and it is unbuildable-by-hobbyists.
2. **Clone the Cybersecurity repo structure verbatim** (skills/<name>/SKILL.md + references/standards.md + workflows.md + scripts/ + assets/, frontmatter with standards fields, When to Use/Prerequisites/Workflow/Verification bodies) on the agentskills.io spec.
3. **Clone the K-Dense operational stack:** Skill Spec Validation CI, security-scan CI (Cisco AI Defense skill-scanner), per-skill pytest suites in isolated envs, auto-versioned releases, docs/skills.md inventory, CONTRIBUTING with schema rules.
4. **Ship evals + benchmarks like SimpleEnglish** — measured before/after per skill ("agent with AeroSkills vs without: X% fewer spec violations, Y% fewer unit errors on worked examples"). Evals were the #1 growth driver in the ASD-STE100 race (SimpleEnglish 2,937★ vs danyuchn/asd-ste100-skill 1,574★ vs hakimzulkufli/asd-ste100-skills 0★ for the same idea).
5. **Cross-harness + distribution from day one:** agentskills.io conformance, plugin.json, `npx skills add`, openskills, prpm, gh skill install, skills.sh listing, 20+ platform claim.
6. **SEP-2640-conformant skills-over-MCP serving** (Resources-based, `skill://` URIs — not FastMCP's divergent SkillsProvider), register in the MCP registry, comment on SEP-2640/skills.json as an aerospace voice. Being the reference aerospace implementation while the WG standardizes = protocol-level first-mover.
7. **Differentiate beyond the copy:** compliance hooks (airworthiness narrative), curriculum alignment (ABET/career tracks — no competitor has it), router skill, and integration skills that invoke the existing computation MCP servers (IO-Aerospace, the-hangar) — turning them into complements instead of competitors.
8. **License Apache-2.0, run the release train, keep a public roadmap.** The niche is a graveyard of 1-commit repos; cadence alone will be a differentiator.
9. **Launch with the data points:** "largest aerospace skills library" is true at ~12 skills of content depth today (devideamax). AeroSkills landing with 50+ standards-mapped, tested, cross-harness skills is not incremental — it's a category launch.

### Timing verdict
- The format (agentskills.io) is stable; the distribution (SEP-2640) is being standardized *now* (draft, v1 scope July 2026) — early participation is cheap, late participation is expensive.
- The adjacent-domain winners (30–40k★ each) are 6–10 months old; the aerospace lane has zero serious entrants (largest dedicated repo 60★, abandoned; largest active 22★).
- ASD-STE100's July 2026 viral moment proved aerospace-standards-as-skills *can* go viral when packaged with evals — but it was writing-focused, not engineering.
- **First-mover window: open, and closing as fast as the WG ships SEP-2640 and as early adopters in aerospace companies standardize their own skill stacks. The winning move is to be the library everyone else's company-internal skills get compared to.**
