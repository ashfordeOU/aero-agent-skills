## Untested axes

| axis | value not reached | why |
| --- | --- | --- |
| hostname | kernel host name | changing it needs administrator rights (scutil --set HostName) and macOS has no user-level UTS namespace; the artefacts were instead scanned for this machine's real name |
| fileorder | reverse creation order on the native filesystem | measured: this filesystem returns directory entries in an order derived from the names, so creating them in reverse order gave the identical readdir sequence -- the axis did not actually move |
| operating system | anything but Darwin 25.6.0 | a single host was available; a Linux or Windows run was not performed |
| cpu architecture | anything but arm64 | no second architecture was available |
| clock | a wall-clock jump between runs | the system clock was not moved; the artefacts were instead scanned for embedded timestamps |

## Reading this honestly

- Every `identical` cell is a statement about this host, this filesystem, these interpreter builds and the sampled cases, and nothing wider.
- The untested table is part of the result, not a caveat appended to it. An axis listed there has no verdict at all.
- `umask` moves the mode bits of the files the child creates; it does not move their content for this pipeline, because the pipeline writes no files of its own. The axis is reported for completeness and its power over this pipeline is low.
