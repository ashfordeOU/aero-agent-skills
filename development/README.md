# Development Department

**Purpose:** what we build — the product, skills, and tooling.

## Workspace
- `src/` — source code
- `builds/` — built artifacts + demos
- `tests/` — tests + verification

## Operating rules
1. ONE main branch; every commit complete; clean at rest
2. Test-first: write the failing test → fix → watch it pass
3. Evidence gate: nothing ships without being exercised
4. Minimal code: no speculative abstractions, simplicity first
5. CI before commit: syntax, tests, security scan

## Inputs
- Research briefs → build decisions
- Product requirements from the founder

## Outputs
- Working builds → ops (deploy) + marketing (demo)
